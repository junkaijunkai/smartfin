Evaluation Architecture

How SmartFin Evaluations Work

SmartFin uses deepeval with Claude Haiku 4.5 as the judge model (LLM-as-a-Judge pattern). The target agent under test uses Claude Sonnet to generate outputs, and the judge model independently scores those outputs against expected results using configurable metrics.

Evaluation Levels

L1 Component Accuracy — Exact field-level extraction correctness (GEval)
L2 Output Quality — Relevancy & faithfulness of free-text explanations
L3 Routing Accuracy — Correct intent classification and agent routing

Metrics Used

Metric Type Description Used In
GEval Custom criteria LLM-judge evaluates actual vs expected output using user-defined criteria string. Supports exact match, semantic match, and structured JSON comparison. Intent, Expense, Budget, Goal
AnswerRelevancyMetric Relevancy Measures whether the generated text is relevant to the input question / context. Penalises off-topic or hallucinated content. Anomaly, Health
FaithfulnessMetric Faithfulness Measures whether the generated text is grounded in the provided retrieval context. Penalises claims not supported by source data. Anomaly, Health

CI Integration Note

These evaluations run in the llm-evaluations job of the CI pipeline, after all quality & security checks pass. They require the ANTHROPIC_API_KEY secret to be configured. If the key is not set, evaluations are gracefully skipped without failing the pipeline.

Command: python -m pytest tests/evals -v -m eval
